# Drive Boston - Greater Boston

A single-player, free-roaming browser driving prototype built with Three.js, TypeScript, Vite, and Rapier. Explore Boston from Charlestown and East Boston to Mattapan and Jamaica Plain, plus Cambridge, Somerville, and Brookline, in an ivory coupe or an inspection helicopter. Only Roslindale, West Roxbury, Hyde Park, and the Harbor Islands are left out. Streets and building models come from Boston's and Cambridge's public data, OpenStreetMap fills the towns without open 3D models, and an offline USGS elevation grid supplies the real terrain. The world streams in 1 km tiles around the player, so the whole 140 km² region is one continuous drive. Desktop is the primary target; touch devices start in the lighter Balanced graphics mode.

## Run

Node.js 24 LTS is recommended.

```sh
npm ci
npm run dev
```

Open the local URL printed by Vite, then select **Start driving**. No API keys, accounts, or runtime map services are needed. All geographic assets ship with the application. The package totals approximately 83 MB before transfer compression, but a session only downloads the 6 MB city index, the 11 MB terrain grid, the 4 MB far-building hulls, and the 1 km building tiles near the player (about 280 KB each, 191 in all). Subsequent visits can reuse the browser cache.

```sh
npm run build
npm run preview
```

The `dist/` directory is a static site. Vite uses a relative base so it can be hosted at a GitHub Pages repository path.

The public prototype is hosted at **https://markleary.github.io/drive-boston/**. The GitHub Actions workflow in `.github/workflows/deploy.yml` builds the site and publishes `dist/` to GitHub Pages on every push to `main`, so merging a pull request deploys it; the workflow can also be started by hand from the repository's Actions tab. The repository's Pages source must be set to GitHub Actions (Settings, Pages) for those deployments to be accepted; the former `gh-pages` branch is no longer used. The workflow only builds and deploys; it does not run the test suites.

To check a build locally, run `npm ci`, `npm run build`, and `npm run preview`.

## Play

Open **M** to browse the atlas and choose one of 49 starting points: the original Back Bay and Mission Hill places, Fenway Park, Kenmore Square, the State House, Downtown Crossing, Chinatown Gate, Boston Common, and the Public Garden, and now Faneuil Hall, the Old North Church, the Custom House, City Hall Plaza, TD Garden, the Museum of Science, the Longfellow Bridge, the Seaport ICA, Castle Island, Dorchester Heights, the JFK Library, Nubian Square, Franklin Park Zoo, Jamaica Pond, the Arnold Arboretum, Mattapan Square, the Bunker Hill Monument, the Charlestown Navy Yard, Maverick Square, Logan Airport, Harvard Stadium, the Chestnut Hill Reservoir, Harvard Square, Harvard Yard, the MIT Great Dome, Kendall Square, Porter Square, Fresh Pond, Davis Square, Union Square, Prospect Hill, Assembly Row, Coolidge Corner, Brookline Village, and Larz Anderson Park. **Mission Hill · Parker Hill** starts on an uphill stretch of Parker Hill Avenue, and **Brigham Circle** explores the Huntington Avenue approach. Every destination outside East Boston has a connected surface-road route from the Boylston Street spawn; the harbor tunnels are not modeled, so Maverick Square and Logan Airport are reached by helicopter or by the atlas. The Mission Hill summit is about 59 m (193 ft) above the original Boylston starting point.

Neighborhood names and boundaries follow the [City of Boston neighborhood GIS layer](https://gisportal.boston.gov/arcgis/rest/services/Basemaps/Boston_Basemap_Cached_WM/MapServer/16) and, for Cambridge, Somerville, and Brookline, the City's surrounding-town layer. That layer calls the Fenway/Kenmore area **Fenway** and identifies **Longwood**, **Bay Village**, and **Leather District** separately. Boston Common and the Public Garden are included explicitly as parks. The GIS layer places both within Beacon Hill, while the city's park directory describes them as Downtown; the game consistently uses the GIS polygons for atlas and HUD labels.

| Input | Action |
| --- | --- |
| 1 / 2 / 3 | Car / Ultra Bee / helicopter |
| W / Up | Accelerate |
| S / Down | Brake, then reverse |
| A / D or Left / Right | Steer |
| Space | Handbrake (car) / both brakes (bike) |
| X | Three-second wheelie while accelerating on the Ultra Bee |
| C | Chase, hood, or aerial camera |
| Mouse drag / wheel | Look around / camera distance |
| M | Open or close the city atlas |
| R | Reset the active vehicle to the Boylston starting point |
| F / N | Horn / sound toggle |
| H | Hide the HUD |
| P | Toggle performance stats |
| Backtick (&#96;) | Toggle debug/location stats |
| Escape | Pause / settings |

In **helicopter mode**, W/S fly forward/backward, A/D move sideways, Q/E turn, **Space rises**, and **Shift descends**. Forward flight reaches about **120 MPH**; releasing the controls brings the aircraft into a hover. The HUD control hints stay visible throughout driving and flight while the HUD is enabled. C switches between chase, cockpit, and overhead views; drag vertically to tilt the aerial inspection view and use the wheel for distance. The instruments display speed in MPH and altitude in feet above the terrain directly below the helicopter. Flight stays inside the prototype boundary, at least 4 meters above terrain and below a ceiling 350 meters above the highest terrain point, with conservative rotor clearance around buildings and continuous collision checks against bridge decks and detailed building openings. This is assisted exploration flight; landing and aerodynamic damage are not simulated.

In **Ultra Bee mode** (2), ride a white/yellow electric dirt bike with a dark-cyan forged-frame likeness, knobby spoked wheels, and a helmeted rider. W/S control throttle and brake/reverse assist; A/D steer and bank the bike. Space applies both brakes. **Accelerate above walking pace, then press X** for a wheelie lasting up to three seconds; braking or releasing the throttle brings the front wheel down. Release and press X again after recovery to repeat. Touch devices gain a Wheelie button; gamepad X/Square performs the same stunt. C includes a rider-eye camera. If a crash leaves the bike on its side, automatic recovery places it upright on the nearest clear road near the crash, preserving the road level at bridges and underpasses. R still returns to the Boylston starting point.

The model uses the **original Ultra Bee X** specifications, rather than the newer HP: [manufacturer reference](https://us.surron.com/ultrabee/) and [specification sheet](https://sur-ronglobal.com/surron-ultra-bee/). Bike mass is 85 kg plus a 70 kg rider, peak output 12.5 kW, rear-wheel torque 440 Nm, wheelbase 1,380 mm, and suspension travel 240 mm. Flat-road simulation reaches 0–50 km/h in about 2.3 seconds and approximately 56 mph. Two Rapier wheel rays, rear-wheel drive, speed-sensitive steering, bank/balance torques, rolling resistance, aerodynamic drag and mild regenerative braking give it motorcycle handling. The wheelie lifts the physical front contact. Automatic rider balance makes keyboard/touch riding accessible; it is a game approximation, not a full motorcycle dynamics model. Electric motor whine replaces the car engine; battery depletion and range are not simulated.

Switching to helicopter launches above your ground vehicle, which stays in the shared traffic/physics world with its brakes held while you fly. Switching back to the same ground vehicle returns to it; choosing the other ground vehicle changes it in place and clears momentum. Map destinations reposition the active vehicle and wait for the tiles around it to stream in. The saved browser position is always the ground vehicle's location; reload starts with the car.

Touch controls appear on touch devices, including extra helicopter lift and turn buttons. A standard gamepad supports left-stick steering, right trigger acceleration, left trigger braking, A handbrake, and B reverse. For flight, the gamepad left stick moves horizontally, the right stick turns, and right/left triggers raise/lower the helicopter. The map includes real building footprints, street labels, City of Boston neighborhood and town boundaries, parks and water, landmarks, pan/zoom, and safe starting points near each landmark. Desktop places appear in a scrolling side panel; phones use a compact scrolling grid below the map. The overview fits the whole metro area, and the target button zooms to your current location. Map/settings screens pause the simulation. Position is saved locally in the browser.

Open **Escape → Graphics** to switch between **Detailed** (contact shading, subtle bloom, frequent local reflection updates) and **Balanced** (lighter shadows and rendering). Both retain the same buildings, streets, traffic, and controls.

Press **P** for performance stats or **backtick (`)** for the debug/location panel; WASD steering remains unchanged. **Copy debug report** captures the active car or helicopter's world coordinates, nearest road name and ID, neighborhood, heading, terrain clearance, view settings, and rendering stats for reporting a problem. Coordinates are meters in the game's local world: X increases east, Z increases south, and Y is height above the local datum, not latitude/longitude or elevation above sea level. Render totals include shadows, reflections, and postprocessing; frame time is a measured frame interval rather than GPU execution time.

## Included

- 117,598 buildings across 140.5 km² of continuous coverage: 76,807 surveyed Boston meshes from 68 city model tiles, 16,889 surveyed Cambridge meshes from the city's 16 model tiles, and 23,902 OpenStreetMap footprints extruded by their tagged height or storey count for Somerville, Brookline, and the few Cambridge blocks the survey omits. All 3,763 models from the central-Boston version remain, with the same vertical normalization. Twenty-two official Boston neighborhood polygons plus the Cambridge, Somerville, and Brookline town polygons define 25 districts.
- 20,167 road paths (14,999 City of Boston centerline paths and 5,168 OpenStreetMap streets for the three towns, snapped together at the city line), 559 independent deck segments where the sources cross water or another level, including 18 restored spans that district clipping had removed, 44,975 curb paths, 1,738 signal locations, and 49 map destinations. Interstates, the Turnpike, Storrow Drive, and tunnels stay out of the street network.
- The world streams: buildings, curbs, park paths, street furniture, and signals load from 1 km tiles around the player, each tile built in slices of a few milliseconds per frame (sized to what the rest of the frame leaves) so the frame rate holds while a neighborhood streams in; a far-city layer draws every building hull in the metro as a flat-shaded box over a coarse terrain sheet, so the skyline and the hills are always visible. Sprawling complexes such as the Prudential, TD Garden, and the Logan terminals draw as terraced massing rather than one slab.
- A bundled 6 m terrain grid from USGS 3DEP covering the whole region. Road-specific grading levels streets across their width and smooths local DEM dips while preserving their longitudinal hills; the metro package ships that grading precomputed, with the ungraded grid beside it. The rendered terrain, Rapier collision mesh, sidewalks, traffic, pedestrians, and helicopter clearance share the corrected grid; road meshes subdivide across slopes and crests.
- Sixteen procedural façade styles: brownstone, redbrick rowhouse, limestone, terracotta, loft, office, modern panel treatments, church masonry/lancets, and five clapboard palettes. Stabilized wall UVs and shallow material relief keep window lines and reflections from rippling across source triangles. Up close, every painted window opens onto a parallax-mapped room behind the glass (plaster walls, floorboards and a rug, a ceiling lamp, a door and a picture, with drapes or a drawn shade in some windows) that moves correctly with the camera; rooms span whole window bays, a random 44% of them switch their lamps on at night (fewer at golden hour), and distant windows return to the filtered painted glazing, lit or dark to match the room behind them.
- Mission Hill triple-decker interpretations on 206 candidate source houses, selected from measured height/footprint, detachedness, the official neighborhood boundary, and residential frontage. Three-floor window trim, cornices, and stacked porches use compatible source walls and setbacks. These are inferred architectural types, not address-verified classifications; the original building shapes stay intact.
- A bounded budget of projecting window surrounds, arches, pediments, cornices, brownstone stoops, railings, and storefronts, distributed across the expanded area and checked against source walls. Building geometry is grouped into spatial chunks for visibility culling.
- Additional architectural details aligned to Boston Public Library, Trinity Church, and 200 Clarendon, including BPL's Boylston-facing arches. Reviewed building identities and religious-use tags override the generic height-based façade rules; satellite imagery is not a classification input.

The Bunker Hill Monument, Dorchester Heights Monument, and Prospect Hill Tower, which the surveys reduce to stubs, are rebuilt as procedural obelisk, tower, and round-tower forms at their mapped positions and real heights.
- The Prudential Tower crown on the surveyed shaft: a dark recessed top floor on slender posts, two cantilevered cream slabs around a tall glass band, original extruded PRUDENTIAL serif lettering on all four faces, and dark metal cladding on the source rooftop penthouse. The glass band and letters light up at night.

## Scope and fidelity

This is a free-roaming exploration prototype of one metropolitan region. The driving surface uses sampled bare-earth terrain with procedural street grading. Source-mapped Bowker/Charlesgate decks and ramps, plus the lower Commonwealth Avenue bridges over the Muddy River, have independent collision surfaces and estimated elevations. Elsewhere, streets that the sources mark as crossing water or another road level get generic 6.4 m decks with smooth approach ramps, including the Charles River bridges to Cambridge; interstates, the Turnpike, Storrow Drive, the Central Artery, and every tunnel remain excluded, which is why East Boston is not connected by road. Longfellow has an original procedural interpretation of its four granite salt-and-pepper towers, eleven steel arch spans, piers, sidewalks, and central rail reservation. Bridge details follow both carriageway ramp profiles, and the rail reservation stays clear of trees. Water surfaces cover the detailed river terrain so the Charles stays water as tiles load, while paved bank roads and underpasses remain visible. Land-side surveyed viaducts have ground-reaching supports; the Zakim cable span and its unfinished Big Dig tunnel connection are unchanged. Bridge guardrails and edge markings follow exposed deck edges, with openings at overlapping ramps and merges; visible barriers and collisions use the same clipped geometry. Road cuts and fine curb ramps are not individually engineered. Raised curb faces and landscaping remain visual detail. Buildings are seated level on their sampled footprint high point, with retaining foundations where needed; this is an approximation on steep sites. Road widths and markings are approximate, and façades and street furniture are artistic interpretations. Storefront labels are fictional; signals use a simplified shared cycle. Pedestrians remain on sidewalk routes and are ambient characters. Most source building surveys date to 2011; the June 2026 model package is not a fresh survey. Most building collisions use conservative convex footprints and can close off courtyards. The Prudential complex, 145 Dartmouth, Fenway Park, the Logan terminals, and the Zakim Bridge instead use their original source triangles, preserving real street, field, and underpass openings. The Prudential crown adds a solid box around its slab overhangs. OpenStreetMap buildings in the towns are flat-roofed or gabled extrusions of mapped footprints, not surveyed massing. Tiles beyond about 1.1 km from the player are drawn as hulls only; a fast helicopter can briefly outrun the detailed tiles. The map offers landmark repositioning, not turn-by-turn navigation. There are no missions, multiplayer, or enterable interiors.

The real model geometry is retained, quantized to 1 cm (2 to 5 cm for the three largest meshes) inside the tiles, with its vertical placement reconciled to the terrain; the game does not bundle photographic façades. Fenway is a detailed exterior/aerial landmark. Its source stadium collision preserves the open field, but the generated field, seats, and stands are decorative and do not establish a playable stadium interior. House façades, porches, planting, and pedestrians are procedural interpretations rather than a record of each real address or tree. See [DATA_SOURCES.md](DATA_SOURCES.md) for exact sources, licenses, filtering, source dates, coordinate conversion, and asset regeneration.

Reviewing unable12’s Slop San Francisco informed the shared-terrain and draped-road architecture used for the Mission Hill expansion. The implementation and procedural art here are original; its source code was not copied.

## Sound assets

The seven shipped MP3s total 47 seconds and approximately 760 KB. They are generated assets, not recordings of the real neighborhood. Playback is entirely local; the browser never calls ElevenLabs or receives an API key. [Audio notes and provenance](public/audio/README.md) describe generation and runtime behavior.

```sh
node scripts/generate-audio.mjs             # Preview; no provider requests
node scripts/generate-audio.mjs --generate  # Generate missing clips only
```

Generation uses `ELEVENLABS_API_KEY` from the local ignored `.env` or shell environment. Existing audio is never overwritten. Normal play and builds do not require a key.

## Validation

```sh
npm run validate:data
npm run test:physics
npm test
npm run build
```

`npm run validate:data` needs the `.venv-data` Python environment described in [DATA_SOURCES.md](DATA_SOURCES.md). Node tests read the shipped tiled package through `tests/helpers/metro-city.mjs`, which loads the tiles of the original central window (or the whole road network) and cuts a whole-city view out of them, so the physics, traffic, and grading suites run against the same data the game streams. Browser tests use Playwright with the installed Google Chrome channel and automatically build and serve an isolated production preview. Physics tests check actual-city driving, braking/reverse, fixed-step consistency, collisions, reset behavior, road adherence, player avoidance, signal stops, sidewalk routes, and parked-car collisions. Flight tests additionally check hover, climb, turn, translation, height/boundary limits, reset, and continuous building clearance. Bridge regressions drive across the restored Harvard, both Longfellow carriageways, and Congress Street spans, verify matching deck joins and traffic coverage, and check water visibility above the detailed Charles terrain. Geometry tests check preserved survey vertices/UV continuity, candidate house classification, Fenway diamond dimensions, and that the batched triangle writer reproduces Three.js box placement, matrix transforms, and flat normals vertex for vertex. Pedestrian tests exercise relocation to Mission Hill, protected nearby actors, route/terrain adherence, stance-foot grounding, and pausing/resuming near a moving car. Browser tests exercise real driving and flight input, vehicle switching, maps, settings, cameras, mobile layout, graphics modes, recorded audio, pause/mute/horn behavior, and WebGL errors. The city expansion flow visits all seven new destinations, drives in Fenway, Beacon Hill, and Chinatown, checks the official neighborhood HUD labels, and inspects Boston Common by helicopter. The Embrace's geometry test checks its 20 ft height, 25 ft width, four bearing arms, and walk-through headroom; a browser test drives into its plaza from Tremont Street. A phone flow verifies every destination remains reachable in the scrolling atlas. Additional regressions drive onto and under the actual Bowker overpass, preserve deck resets, fly against its deck edges, keep the Huntington/Dartmouth passages open, verify directional signal clearance and transit dwell/avoidance, and exercise the integrated MBTA services in the browser.

## Structure

- `scripts/`: reproducible GIS and OBJ preprocessing, offline grading, and the tile packer.
- `public/data/`: the city index, terrain and far-building sidecars, 1 km tiles, and source provenance.
- `src/physics/`: Rapier simulation.
- `src/render/`: scene, materials, landmark details, and player vehicle.
- `src/simulation/`: traffic, road helpers, and sound.
- `src/ui/`: DOM interface and Canvas maps.

The simulation uses a fixed 60 Hz step and remains separate from the Three.js view. Current work focuses on visual polish and free-roaming driving across the region. Future improvements can refine street grades, junctions, bridge profiles, and district landmarks without replacing the shared terrain foundation or the tile format.
