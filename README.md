# Drive Boston - Greater Boston

A single-player, free-roaming browser driving prototype built with Three.js, TypeScript, Vite, and Rapier. Explore Boston from Charlestown and East Boston to Mattapan and Jamaica Plain, plus Cambridge, Somerville, and Brookline, in an ivory coupe or an inspection helicopter. Only Roslindale, West Roxbury, Hyde Park, and the Harbor Islands are left out. Streets and building models come from Boston's and Cambridge's public data, OpenStreetMap fills the towns without open 3D models, and an offline USGS elevation grid supplies the real terrain. The world streams in 1 km tiles around the player, so the whole 140 km² region is one continuous drive. Desktop is the primary target. Touch devices start in Balanced mode with direct canvas rendering, 1024-pixel shadows, nearby skyline chunks, and a smaller detailed neighborhood radius. Mobile omits ambient occlusion, bloom, multisampled HDR buffers, dynamic reflections, raised curb decoration, extra facade/rooftop meshes, and startup night-shader warmup; selecting Detailed on a touch device retains these memory limits. Mobile road buffers share identical vertices without changing their triangles, and mobile tile assembly avoids an additional full-tile buffer repack. Night shaders compile when Night is first selected, which may briefly pause rendering.

## Run

Node.js 24 LTS is recommended.

```sh
npm ci
npm run dev
```

Open the local URL printed by Vite, then select **Start driving**. No API keys, accounts, or runtime map services are needed. All geographic assets ship with the application. The package totals approximately 86 MB before transfer compression, but a session only downloads the 6 MB city index, the 11 MB terrain grid, the 4 MB far-building hulls, and the 1 km building tiles near the player (about 280 KB each, 191 in all). Subsequent visits can reuse the browser cache.

```sh
npm run build
npm run preview
```

The `dist/` directory is a static site. Vite uses a relative base so it can be hosted at a GitHub Pages repository path.

The web manifest, Android icons, and Apple home-screen tags allow installation from the browser’s **Add to Home Screen** action. Android requests fullscreen; iOS opens without Safari’s toolbar when **Open as Web App** is enabled. Both orientations are supported. This is an online game; home-screen installation does not cache the city for offline use. Static Open Graph and Twitter metadata use `public/social-preview.jpg`, a 1200 × 630 capture of actual desktop gameplay, for shared links.

The public prototype is hosted at **https://markleary.github.io/drive-boston/**. The GitHub Actions workflow in `.github/workflows/deploy.yml` builds the site and publishes `dist/` to GitHub Pages on every push to `main`, so merging a pull request deploys it; the workflow can also be started by hand from the repository's Actions tab. The repository's Pages source must be set to GitHub Actions (Settings, Pages) for those deployments to be accepted; the former `gh-pages` branch is no longer used. The workflow only builds and deploys; it does not run the test suites.

To check a build locally, run `npm ci`, `npm run build`, and `npm run preview`.

## Play

Open **M** to browse the atlas and choose one of 49 starting points: the original Back Bay and Mission Hill places, Fenway Park, Kenmore Square, the State House, Downtown Crossing, Chinatown Gate, Boston Common, and the Public Garden, and now Faneuil Hall, the Old North Church, the Custom House, City Hall Plaza, TD Garden, the Museum of Science, the Longfellow Bridge, the Seaport ICA, Castle Island, Dorchester Heights, the JFK Library, Nubian Square, Franklin Park Zoo, Jamaica Pond, the Arnold Arboretum, Mattapan Square, the Bunker Hill Monument, the Charlestown Navy Yard, Maverick Square, Logan Airport, Harvard Stadium, the Chestnut Hill Reservoir, Harvard Square, Harvard Yard, the MIT Great Dome, Kendall Square, Porter Square, Fresh Pond, Davis Square, Union Square, Prospect Hill, Assembly Row, Coolidge Corner, Brookline Village, and Larz Anderson Park. **Mission Hill · Parker Hill** starts on an uphill stretch of Parker Hill Avenue, and **Brigham Circle** explores the Huntington Avenue approach. Every destination outside East Boston has a connected surface-road route from the Boylston Street spawn; the harbor tunnels are not modeled, so Maverick Square and Logan Airport are reached by helicopter or by the atlas. The Mission Hill summit is about 59 m (193 ft) above the original Boylston starting point.

Neighborhood names and boundaries follow the [City of Boston neighborhood GIS layer](https://gisportal.boston.gov/arcgis/rest/services/Basemaps/Boston_Basemap_Cached_WM/MapServer/16) and, for Cambridge, Somerville, and Brookline, the City's surrounding-town layer. That layer calls the Fenway/Kenmore area **Fenway** and identifies **Longwood**, **Bay Village**, and **Leather District** separately. Boston Common and the Public Garden are included explicitly as parks. The GIS layer places both within Beacon Hill, while the city's park directory describes them as Downtown; the game consistently uses the GIS polygons for atlas and HUD labels.

| Input | Action |
| --- | --- |
| 1 / 2 / 3 | Car / Ultra Bee / helicopter |
| W / Up | Accelerate |
| S / Down | Brake, then reverse |
| A / D or Left / Right | Steer |
| Space | Handbrake (car) / both brakes (bike) |
| X | Three-second wheelie while accelerating on the Ultra Bee |
| C | Chase, hood, or aerial camera |
| Mouse drag / wheel | Look around / camera distance |
| M | Open or close the city atlas |
| R | Reset the active vehicle to the Boylston starting point |
| F / N | Horn / sound toggle |
| H | Hide the HUD |
| P | Toggle performance stats |
| Backtick (&#96;) | Toggle debug/location stats |
| Escape | Pause / settings |

In **helicopter mode**, W/S fly forward/backward, A/D move sideways, Q/E turn, **Space rises**, and **Shift descends**. Forward flight reaches about **120 MPH**; releasing the controls brings the aircraft into a hover. The HUD control hints stay visible throughout driving and flight while the HUD is enabled. C switches between chase, cockpit, and overhead views; drag vertically to tilt the aerial inspection view and use the wheel for distance. The instruments display speed in MPH and altitude in feet above the terrain directly below the helicopter. Flight stays inside the prototype boundary, at least 4 meters above terrain and below a ceiling 350 meters above the highest terrain point, with conservative rotor clearance around buildings and continuous collision checks against bridge decks and detailed building openings. This is assisted exploration flight; landing and aerodynamic damage are not simulated.

In **Ultra Bee mode** (2), ride a white/yellow electric dirt bike with a dark-cyan forged-frame likeness, knobby spoked wheels, and a rider wearing an original red Fox V1 Toxsyk-inspired motocross helmet with a long peak, vented chin guard, full black face mask, and black/white graphics. W/S control throttle and brake/reverse assist; A/D turn the front wheel, forks and handlebars as the bike banks; the rider’s hands follow the grips. Space applies both brakes. **Accelerate above walking pace, then press X** for a wheelie lasting up to three seconds; braking or releasing the throttle brings the front wheel down. Release and press X again after recovery to repeat. Touch devices gain a Wheelie button; gamepad X/Square performs the same stunt. C includes a rider-eye camera. If a crash leaves the bike on its side, automatic recovery places it upright on the nearest clear road near the crash, preserving the road level at bridges and underpasses. R still returns to the Boylston starting point.

The model uses the **original Ultra Bee X** specifications, rather than the newer HP: [manufacturer reference](https://us.surron.com/ultrabee/) and [specification sheet](https://sur-ronglobal.com/surron-ultra-bee/). Bike mass is 85 kg plus a 70 kg rider, peak output 12.5 kW, rear-wheel torque 440 Nm, wheelbase 1,380 mm, and suspension travel 240 mm. Flat-road simulation reaches 0–50 km/h in about 2.3 seconds and approximately 56 mph. Two Rapier wheel rays, rear-wheel drive, speed-sensitive steering with matching tire and lean targets, bank/balance torques, rolling resistance, aerodynamic drag and mild regenerative braking give it motorcycle handling. The wheelie lifts the physical front contact. Automatic rider balance makes keyboard/touch riding accessible; it is a game approximation, not a full motorcycle dynamics model. Electric motor whine replaces the car engine; battery depletion and range are not simulated.

Switching to helicopter launches above your ground vehicle, which stays in the shared traffic/physics world with its brakes held while you fly. Switching back to the same ground vehicle returns to it; choosing the other ground vehicle changes it in place and clears momentum. Map destinations reposition the active vehicle and wait for the tiles around it to stream in. The saved browser position is always the ground vehicle's location; reload starts with the car.

Touch devices default to a proportional steering pad on the left and separate Gas/Brake pedals on the right. Brake stops the vehicle without selecting reverse; the D/R selector unlocks only near a standstill. **Settings → Touch controls** offers a saved **Combined joystick** alternative: up accelerates, left/right steer, and down brakes then reverses. Handbrake remains a separate action, and the bike adds Wheelie. Mobile vehicle switching is in settings; helicopter mode keeps dedicated movement, turn, and altitude buttons. Portrait hides the minimap, keeps the full atlas available through the map button, and reframes the chase camera above the thumb controls. Landscape places the minimap at the upper left. The atlas supports touch pan and pinch zoom. Rotating, leaving the app, opening a menu, or changing controls releases held input. A standard gamepad supports left-stick steering, right trigger acceleration, left trigger braking, A handbrake, and B reverse. For flight, the gamepad left stick moves horizontally, the right stick turns, and right/left triggers raise/lower the helicopter. While driving or riding, the label at the top of the HUD names your street and, below it, the next cross street ahead in your direction of travel. The map includes real building footprints, street labels, City of Boston neighborhood and town boundaries, parks and water, landmarks, pan/zoom, and safe starting points near each landmark. Desktop places appear in a scrolling side panel; phones use a compact scrolling grid below the map. The overview fits the whole metro area, and the target button zooms to your current location. Map/settings screens pause the simulation. Position is saved locally in the browser.

Open **Escape → Graphics** to switch between **Detailed** (contact shading, subtle bloom, frequent local reflection updates) and **Balanced** (lighter shadows and rendering). Both retain the same buildings, streets, traffic, and controls.

Press **P** for performance stats or **backtick (`)** for the debug/location panel; WASD steering remains unchanged. **Copy debug report** captures the active car or helicopter's world coordinates, nearest road name and ID, neighborhood, heading, terrain clearance, view settings, and rendering stats for reporting a problem. Coordinates are meters in the game's local world: X increases east, Z increases south, and Y is height above the local datum, not latitude/longitude or elevation above sea level. Render totals include shadows, reflections, and postprocessing; frame time is a measured frame interval rather than GPU execution time.

## Scope and fidelity

This is a free-roaming exploration prototype of one metropolitan region. The driving surface uses sampled bare-earth terrain with procedural street grading. Source-mapped Bowker/Charlesgate decks and ramps, plus the lower Commonwealth Avenue bridges over the Muddy River, have independent collision surfaces and estimated elevations. Elsewhere, streets that the sources mark as crossing water or another road level get generic 6.4 m decks with smooth approach ramps, including the Charles River bridges to Cambridge; interstates, the Turnpike, Storrow Drive, the Central Artery, and every tunnel remain excluded, which is why East Boston is not connected by road. Longfellow has an original procedural interpretation of its four granite salt-and-pepper towers, eleven steel arch spans, piers, sidewalks, and central rail reservation. Bridge details follow both carriageway ramp profiles, and the rail reservation stays clear of trees. Harvard Bridge has continuous deck joins, a tapered Boston approach, and painted Smoot ticks and labels on its eastern sidewalk. Water stays horizontal at a consistent estimated level for each basin or river reach, intersects sloping banks, and preserves paved bank roads and underpasses as tiles load. Land-side surveyed viaducts have ground-reaching supports; the Zakim cable span and its unfinished Big Dig tunnel connection are unchanged. Bridge guardrails and edge markings follow exposed deck edges, with openings at overlapping ramps and merges; visible barriers and collisions use the same clipped geometry. Road cuts and fine curb ramps are not individually engineered. Raised curb faces and landscaping remain visual detail. Buildings are seated level on their sampled footprint high point, with retaining foundations where needed; this is an approximation on steep sites. Road widths and markings are approximate, and façades and street furniture are artistic interpretations. Storefront labels are fictional; signals use a simplified shared cycle. Pedestrians remain on sidewalk routes and are ambient characters. Most source building surveys date to 2011; the June 2026 model package is not a fresh survey. Buildings whose convex footprints cross ground-level road centerlines automatically use detailed triangle collision, preserving openings that exist in the source mesh. The Prudential complex, 145 Dartmouth, NEXUS, Fenway Park, the Logan terminals, and the Zakim Bridge also retain explicit exact-mesh handling. BUMC on Massachusetts Avenue required a separate geometry correction: the original survey contained walls across the street, so selecting its source triangles alone did not open the crossing. Its corrected passage has an estimated six metres of clearance and is tested by driving through both facades in both directions, with additional bus-height checks across the lanes. Other buildings retain convex collision proxies that can close courtyards; a city-wide clearance audit flags source-model roadway intrusions for review. The Prudential crown adds a solid box around its slab overhangs. OpenStreetMap buildings in the towns are flat-roofed or gabled extrusions of mapped footprints, not surveyed massing. Tiles beyond about 1.1 km from the player are drawn as hulls only; a fast helicopter can briefly outrun the detailed tiles. The map offers landmark repositioning, not turn-by-turn navigation. There are no missions, multiplayer, or enterable interiors.

The real model geometry is retained, quantized to 1 cm (2 to 5 cm for the three largest meshes) inside the tiles, with its vertical placement reconciled to the terrain; the game does not bundle photographic façades. Fenway is a detailed exterior/aerial landmark. Its source stadium collision preserves the open field, but the generated field, seats, and stands are decorative and do not establish a playable stadium interior. House façades, porches, planting, and pedestrians are procedural interpretations rather than a record of each real address or tree. See [DATA_SOURCES.md](DATA_SOURCES.md) for exact sources, licenses, filtering, source dates, coordinate conversion, and asset regeneration.

Reviewing unable12’s Slop San Francisco informed the shared-terrain and draped-road architecture used for the Mission Hill expansion. The implementation and procedural art here are original; its source code was not copied.

## Sound assets

The seven shipped MP3s total 47 seconds and approximately 760 KB. They are generated assets, not recordings of the real neighborhood. Playback is entirely local; the browser never calls ElevenLabs or receives an API key. [Audio notes and provenance](public/audio/README.md) describe generation and runtime behavior.

```sh
node scripts/generate-audio.mjs             # Preview; no provider requests
node scripts/generate-audio.mjs --generate  # Generate missing clips only
```

Generation uses `ELEVENLABS_API_KEY` from the local ignored `.env` or shell environment. Existing audio is never overwritten. Normal play and builds do not require a key.

## Validation

```sh
npm run validate:data
npm run test:physics
npm test
npm run build
```

`npm run validate:data` needs the `.venv-data` Python environment described in [DATA_SOURCES.md](DATA_SOURCES.md). Node tests read the shipped tiled package through `tests/helpers/metro-city.mjs`, which loads the tiles of the original central window (or the whole road network) and cuts a whole-city view out of them, so the physics, traffic, and grading suites run against the same data the game streams. Browser tests use Playwright with the installed Google Chrome channel and automatically build and serve an isolated production preview; use `npx playwright test --config playwright.edge.config.ts` to run them in installed Microsoft Edge. Physics tests check actual-city driving, braking/reverse, fixed-step consistency, collisions, reset behavior, road adherence, player avoidance, signal stops, sidewalk routes, and parked-car collisions. Flight tests additionally check hover, climb, turn, translation, height/boundary limits, reset, and continuous building clearance. Bridge regressions drive across the restored Harvard, both Longfellow carriageways, and Congress Street spans, verify matching deck joins and traffic coverage, and check water visibility above the detailed Charles terrain. Geometry tests check preserved survey vertices/UV continuity, candidate house classification, Fenway diamond dimensions, and that the batched triangle writer reproduces Three.js box placement, matrix transforms, and flat normals vertex for vertex. Pedestrian tests exercise relocation to Mission Hill, protected nearby actors, route/terrain adherence, stance-foot grounding, and pausing/resuming near a moving car. Browser tests exercise real driving and flight input, vehicle switching, maps, settings, cameras, mobile layout, graphics modes, recorded audio, pause/mute/horn behavior, and WebGL errors. The city expansion flow visits all seven new destinations, drives in Fenway, Beacon Hill, and Chinatown, checks the official neighborhood HUD labels, and inspects Boston Common by helicopter. The Embrace's geometry test checks its 20 ft height, 25 ft width, four bearing arms, and walk-through headroom; a browser test drives into its plaza from Tremont Street. A phone flow verifies every destination remains reachable in the scrolling atlas. Additional regressions drive onto and under the actual Bowker overpass, preserve deck resets, fly against its deck edges, keep the Huntington/Dartmouth passages open, drive Massachusetts Avenue beneath the BUMC link and Western Avenue beside NEXUS where convex proxies would wall off the street, verify directional signal clearance and transit dwell/avoidance, and exercise the integrated MBTA services in the browser.

## Structure

- `scripts/`: reproducible GIS and OBJ preprocessing, offline grading, and the tile packer.
- `public/data/`: the city index, terrain and far-building sidecars, 1 km tiles, and source provenance.
- `src/physics/`: Rapier simulation.
- `src/render/`: scene, materials, landmark details, and player vehicle.
- `src/simulation/`: traffic, road helpers, and sound.
- `src/ui/`: DOM interface and Canvas maps.

The simulation uses a fixed 60 Hz step and remains separate from the Three.js view. Current work focuses on visual polish and free-roaming driving across the region. Future improvements can refine street grades, junctions, bridge profiles, and district landmarks without replacing the shared terrain foundation or the tile format.

Static streamed details use material-compatible Three.js `BatchedMesh` submissions with 128 m triangle chunks and per-object frustum culling. This keeps the source geometry, UVs, materials and shadow detail while reducing work outside the view. Traffic body and wheel batches also cull each vehicle separately for the view, shadows and reflections. The postprocessing chain keeps 4× MSAA on the HDR scene pass; fullscreen AO/bloom composition uses a single-sample target. Tile building budgets spare work toward a 60 Hz frame interval, with a small minimum slice so streaming still progresses under load. Performance remains dependent on the viewpoint, display size, GPU and loading state.
