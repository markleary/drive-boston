# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Free-roaming browser driving/flying/walking prototype of Greater Boston (every Boston neighborhood except Roslindale, West Roxbury, Hyde Park and the Harbor Islands, plus Cambridge, Somerville, Brookline, Chelsea, Everett, Medford, Malden and Melrose) built with Three.js, TypeScript, Vite, and Rapier (`@dimforge/rapier3d-compat`). All geographic data ships as static files in `public/data/` and streams in 1 km tiles; there are no runtime map services or API keys. README.md describes gameplay and scope; DATA_SOURCES.md documents data sources, licenses, coordinate conversion, and how to regenerate assets.

## Commands

Node.js 24 is expected (the node tests rely on its native TypeScript type stripping).

```sh
npm ci
npm run dev              # Vite dev server on 127.0.0.1
npm run build            # tsc --noEmit type check, then vite build to dist/
npm run preview          # serve dist/

npm run test:physics     # node --test tests/*.test.mjs (unit/physics/geometry)
npm test                 # Playwright browser tests (tests/*.spec.ts)
npm run validate:data    # .venv-data/bin/python scripts/validate-city.py on public/data
npm run audit:furniture  # node scripts/audit-street-furniture.mjs: every tree, lamp, name sign, walk and kerbside car against the roadway and stalls the tiles draw (about 40 s)
```

Single tests:

```sh
node --test tests/helicopter.test.mjs
node --test --test-name-pattern="hold altitude" tests/helicopter.test.mjs
npx playwright test tests/flight.spec.ts
npx playwright test -g "helicopter: lift"
```

Playwright uses the installed Google Chrome channel, runs serially (1 worker, 90 s timeout), and its `webServer` always runs `npm run build && npm run preview --port 4173` first, so every Playwright run includes a full production build. Browser tests drive the game through `window.__backbay` (set at the end of `boot()` in `src/main.ts`), which exposes `snapshot()`, `travelTo(x, z, yaw)` (streams the tiles around a point and places the car there) and other diagnostic hooks; extend that object when a spec needs new state.

## Architecture

- `src/main.ts` is the single orchestrator: `boot()` fetches `city.json`, resolves its sidecars (`resolveCity()` in `src/simulation/city-tiles.ts` decodes the gzip int16 elevation grid, the DBF2 far-building hulls and the building index), wires UI callbacks, builds the world, physics, traffic, transit, pedestrians, helicopter, and audio, then runs the render loop. Simulation advances on a fixed 60 Hz step independent of the Three.js view.
- **Shared terrain is the foundation.** `prepareRoadTerrain()` (`src/simulation/road-grading.ts`) levels the street corridor (pavement plus the `WALK` sidewalk allowance on each side) across its width, drops a side-hill street toward its lower edge instead of banking it, and protects surveyed building bases outside the corridor. The metro package ships that result precomputed by `scripts/grade-terrain.mjs` (`city.elevation.graded`, raw grid kept in `elevation-source.bin`); `main.ts` only grades in-process for a legacy whole-city `city.json`. Rendering, Rapier collision, traffic, pedestrians, sidewalks, and helicopter clearance all query the same grid via `sampleElevation()` / `sampleDriveSurface()` (`src/simulation/terrain.ts`, `road-surfaces.ts`), so any terrain or road-surface change affects all of them. Never run `buildTerrainGeometryData()` or `prepareRoadTerrain()` on the full 2774 x 4109 metro grid in a test; use `windowCity()` from `tests/helpers/metro-city.mjs`.
- **Street surfaces follow the curbs, not the width guess.** Road widths in `city.json` are name/class assumptions; the curbs are a survey (Boston GIS layer 6) or, in the towns, synthetic lines with filleted corners (one union of every town street's pavement, taken from the streets as their sources mapped them, `mapped_streets`: GEOS notes that union anew whenever its input changes, and a rerun knows a tile's earlier town curbs only by drawing them again, so the pieces the Turnpike stage changes or takes out keep their place in it; without that, 12 m of Carlton Street and Brookline's copies of one bridge moved curbs in 68 tiles as far as Melrose and left the old loop beside the new one; the records `connect-source-seams.py` takes out as a second source's copies keep their place in it the same way, after the other streets, since the union does not depend on the order of its input, and `copy_curb_regions` then cuts the town curb along such a record on each side where Boston's survey has the street's curb at half its stations or more, within the record's pavement grown by the fillet radius, and on both sides of a copy that lay on a Boston bridge, while `town_side_survey` puts back, from the raw survey, the surveyed curbs there that `survey_curbs` drops for having their middle vertex inside a town: Saint Mary's Street keeps its surveyed 8 m roadway instead of the town's 12.2 m outline round it, and nothing outside that tile's curbs moves; a mitred chunk of an earlier build that is no longer among the regenerated ones is recognized on the towns' exact mitred outlines, `on_mitred_outline`, vertex for vertex). `scripts/build-street-surfaces.py` (library `scripts/street_surfaces.py`) measures the roadway between the curbs at 1 m stations and writes per-tile `pavements` (left/right edge polylines in centimetres from the tile origin, sidewalk-inventory presence per side), `sidewalks` (Boston Sidewalk Inventory polygons, brick flagged; a polygon that outlines a whole parkway island keeps only its recorded width, `outline_strip`), `islands` (closed curb faces to fill with concrete) and `driveways` (OpenStreetMap service roads measured to the curbs the same way, surface lots from `data-source-cache/osm-metro-driveways.json`, plus the curb faces they enter, dissolved into asphalt fills one connected group of touching shapes at a time, `connected_groups` in `driveway_surfaces`: one `unary_union` over the metro hands every polygon back with its ring begun wherever the pairing of the inputs left it, so two house lanes fewer rewrote the driveways of 195 tiles, and a group's surfaces must follow from its own shapes alone), plus `pavedWidth` on measured roads. Before measuring, Boston curb stretches in parkland beyond every street's measuring reach are found on the raw survey (`stale_stretches` over `data-source-cache/layer-6.json`, so a rerun sees the same ones) and cut from the tile curbs and from the inventory sidewalks beside them (`cut_stale_curbs`, `cut_stale_sidewalk`) as remnants of removed roadways; a centerline Boston Segments drew inside a curbed park edge (Riverway northbound at Longwood runs 1.5 m inside the splitter island, Arborway segments inside the median) is moved onto the roadway before measuring (`move_park_edge_centerlines`: a lane, 2.5 m, beyond the park's curb or the middle of a narrower roadway, tapering over 12 m, endpoints fixed so junctions keep their connectivity, written back to `city.json` roads so traffic and lane markings follow, the source line kept as `sourcePoints` and restored at the start of every run so a rerun redoes the same move; kept only where it leaves fewer such stations and crosses the same building footprints as the source line, so the `roadOverlaps` metadata from `building_clearance.py` stays valid), and a station such a move cannot take out of the park (a road ending inside the island, a stretch under 3 m is ignored) is paved between that curb and the next one beyond it on the same side (`mask_park_edges`, kept by `clean_side` whatever the neighbours measure, not counted in `pavedWidth`) instead of across the park. `tile-builder.ts` drapes the asphalt between those edges (`drapedStripInto`), draws a 2.9 m sidewalk band only on sides without an inventory polygon, and falls back to the constant-width ribbons for roads without a record (decks). The compiled polygons themselves (`streetPavement`, `streetSidewalks`, the inventory sidewalks, driveways, islands, frontages, and the park lawns and plazas in `city-parks.ts`) are draped by `src/render/draped-surface.ts` (`DrapedSurface`, one indexed mesh per layer): each earcut triangle is clipped against the terrain cells and diagonals it covers, with every crossing computed from the same numbers wherever it is met (an earcut edge's own endpoints in index order, a grid line's constant) so coincident points are bit-identical and weld by exact comparison (an earcut edge that runs along a clip line has no crossing with it: the embankment polygons carry millimetre vertices on cell diagonals, where x + z rounds to either side, so `clip` counts such an edge's ends as on the line and `meet` never divides by the difference of two equal distances); the fragments inside one terrain triangle cancel their shared edges, the outline that remains drops the vertices no outline turns at and is triangulated again (holes and outlines touching in a point included; a terrain triangle whose outline fails its area check keeps its fragments), and cells no boundary comes near are taken whole. That is the same coverage on the same planes in about a fifth of the triangles and a tenth of the bytes of the per-fragment triangle soup `parkSurfaceSteps` (`area-surfaces.ts`) writes, which water sheets, shore banks, the Frog Pond apron and the landmark surfaces still use. Draped layers shade with the terrain mesh's own vertex normals (`terrainVertexNormal` in `terrain.ts`, which the tile terrain writes too) interpolated across each terrain triangle, so their geometry must stay indexed (`splitStaticGeometrySteps` and the batcher handle indexed parts). Storefront setbacks and traffic lane offsets use `pavedWidth ?? width` (a one-way class avenue gets its second lane only where the measured roadway is at least 6.5 m wide); street trees, lamps, name signs, sidewalk walkers and kerbside cars do not (they follow the drawn roadway itself, next entry), and crosswalk stripes span the pavement edges at their own station (`pavementSpan`), widened across the record of a twin carriageway adjoining it (`roadwaySpan`: edges aligned within cosine 0.8, overlapping or touching within .5 m, adding at most one roadway of the own width plus 2 m, no chaining; a parkway's second one-way centerline, not a cross street's junction mouth or a wider street alongside). `src/simulation/crosswalks.ts` (`planCrosswalks`) places them at junctions only: a `junctionIndex` over every road vertex (OSM ways are not split at every T) finds the legs at a road end or mid-vertex, the station is walked along the road until it has left every crossing record (`insideRecord`; a connector under 18 m or a road without a record counts its median width) plus a 1 m setback, a road ending at the node (a stem) is always striped, a road continuing through only where a comparable street (0.75 of its nominal width) meets it or a signal stands within 25 m, alleys, unnamed ways, dead ends and mid-street splits never, and crosswalks on one roadway closer than 12 m keep the signal's, then the stem's, then the wider cross street's (twin carriageways split at different nodes); a tile plans every road within 40 m of its owned roads' extents (a road owned by its midpoint can end 200 m into the next tile) in a tile-independent order and draws the owned ones, so the thinning agrees across tile borders (Boylston Street between tiles -4_2 and -5_2). Records live in the tile that owns the road's midpoint, so each tile also carries `borderPavements`, copies of other tiles' records that run alongside its roads 8 m from each end as candidates for the `roadwaySpan` test (`border_records` on the roads the renderer may stripe, `stripes_crosswalks`, at stations walked 8 m along the line like `stationAlong`, `crosswalk_stations`; `shares_roadway`: an edge crossing the station's across line within 40 m at a direction within cosine 0.8 of the road's; Edwin H. Land Boulevard splits between tiles 0_-2 and -1_-2), read for the spans only. Park lawns carry the same polygon-offset slope factor as the sidewalk material (`city-parks.ts`, bias 3 between the sidewalks' 2 and the terrain's 4) so the centimetre height order, not draw order, decides where a surveyed sidewalk overlaps a lawn. Three more things ride in the tile headers this stage writes. The roadway beside a highway deck's lanes (`highwayPavements`, the aprons the highway stage recorded, see below) is compiled into `streetPavement` with the streets. A curb with nothing attached is never drawn: `bare_curbs` lists per tile (`bareCurbs`, flat [curb index, from cm, to cm]) every stretch of `BARE_RUN` (2 m) or more that has no roadway, driveway or lot, island, sidewalk, highway record, deck or park path within `ATTACH` (0.6 m); the curbs themselves stay in the tile, since the next run measures the streets from them, and `tile-builder.ts` skips the stretches (`bareCurbStretches` in `tile-format.ts`). Surface lots carry their parking stalls (`scripts/parking_lots.py`: rows square to the mapped `parking_aisle` ways, else rows in the direction that holds the most, kerbside bays in a strip too shallow for a stall, clear of aisles, service roads, buildings and street roadways, and `DECK_ROOM` (1 m) clear of every highway deck and cut. They are laid once the surfaces are compiled, on what the tiles draw: a stall lies wholly on the asphalt of the lots and driveways (the tiles' `driveways`) and touches no `streetPavement` and no `streetSidewalks` (the band beside a street with no surveyed sidewalk lies under the asphalt of a lot mapped out to the curb, and is where the street's walkers pace and its trees and lamps stand), and a lot is laid out as it is drawn (`drawn_pieces`: one beyond the playable coverage has no asphalt and so no stalls, one across the coverage's edge or cut around an inventory sidewalk is laid out part by part, its rows centred in what is paved). The ribbon of a street's median width about its centre line is not its roadway, and OpenStreetMap's lots cover the whole envelope while asphalt is drawn inside the coverage only: 82 stalls had stood in street pavement (Newmarket Square's parking is mapped inside its curbs), 13,434 off any drawn asphalt (13,047 of them beyond the coverage, on bare ground) and 3,534 on a street's sidewalk band, 16,939 of 131,373 in all. `misplaced` is the same test on a finished package, and `validate-city.py` fails on any stall it names. No two stalls share ground either: OpenStreetMap holds a few lots twice (a second way over the first, a section mapped again inside its lot; seven groups, the 3.5 ha lot at Fresh Pond in Cambridge among them), which are laid out once as their union (`merged`: lots that share half of the smaller one), a lot that still overlaps another keeps off the stalls already laid there, and `crowded` is the validator's check (263 stalls had stood exactly on another, two cars under one pool key, and 997 pairs of cars overlapped). Per tile `parking`, flat [x cm, z cm, yaw in hundredths of a degree]): `src/simulation/parking-lots.ts` parks a car in a fixed 58% of them, the same on every visit (`stallDraw` hashes the stall's place), of the models no longer than a stall (`PARKED_TYPES`: rows stand nose to nose, and a pickup, 5.9 m in a 5.2 m stall, stood in the car beyond it), and `src/render/parking-lots.ts` paints the stall lines a tile at a time (desktop only) and draws the nearest cars from one pool of the traffic's models (220 within 520 m on desktop, 30 within 150 m on a phone; solid within 70 m). A slot of that pool is bound to one model (`slotType`: an instance of the fleet keeps its geometry), so the pool is shared out by model: `nearestParked` takes of each model the nearest the pool has slots for and `poolSlots` gives a car a free slot of its own model or none. The nearest 220 whatever their model overrun some model's slots nearly every time, and such a car had stood in its stall as another model with its own collision box. The pool's lamps follow the lighting with the kerbside cars' (`setNight`, through `setParkedNight` in `main.ts`). `validate-city.py` holds the three lists to `provenance.streetSurfaces` (`highwayAprons`, `bareCurbs`, `parkingStalls`).
- **What stands beside a street follows the roadway as the tiles draw it, not the street's median width.** `pavedWidth` is one number a road and the centre line seldom runs down the middle of the roadway: Newmarket Square's roadway is 21 m wide under a median of 9.2 m, Blue Hill Avenue's carriageways lie to one side of the lines that stand for them, Back Street widens for a bay. Set at `pavedWidth / 2 + 2` from the centre line, 1,504 of 106,070 street trees, 993 lamps and 222 name signs stood in drawn street pavement, and 7,335 of 120,422 walker stretches ran partly in it. `src/simulation/drawn-streets.ts` (`drawnStreets(tile)`, built once a tile in about 3 ms and kept with it) indexes a tile's compiled `streetPavement` by 8 m cell: `paved`, `near` (pavement within a margin, `CLEARANCE` at most), `spans` (the paved stretches of a line, known as far as the tile's border and no farther), `stall` and `lot` (the tile's parking stalls and lot asphalt), `inset` and `within` (room to the border). `src/simulation/street-furniture.ts` holds the rule. `roadwayEdge` looks along the perpendicular through a station: the road's own roadway is the paved stretch its centre line lies in (the nearest within half the nominal width where the line itself runs off the pavement), unless that stretch runs on past `REACH` (36 m) or the pavement beyond the nominal edge is another street's (`streetRibbons().crossing`: a junction mouth, or the second carriageway of one roadway, which has stations of its own). `vergePlace` stands the place `VERGE` (2 m) beyond that edge, or midway to the next roadway where a median is narrower than two verges, with its room to every roadway (`TREE_ROOM` 1.2 m for the 1.7 m grate, `LAMP_ROOM` 0.6, `SIGN_ROOM` 0.4) and half that to every stall. **A tile knows its own ground only** (its polygons are clipped at its border), so a station and side is planted by the tile its roadway ends in: the station's own tile, or the next one when the perpendicular comes into it on the roadway no farther from the centre line than the nominal edge and a metre (the station's tile then returns nothing; over all 128,290 station sides, each tried against the nine tiles about it, none is planted twice). A place keeps its room inside the border (`postClear`), and where the border lies within that room, or between the place and the kerb, or lot asphalt lies within a stall's reach of the border (a stall is listed by the tile its centre stands in), the place slides along the street (`SLIDES`: 3 then 6 m, either way) to ground the tile sees all round. What a tile cannot see it does not plant on: the rule holds for any package, and a street running along a tile border within its room loses that side's places. `tileFurnitureSteps` is the tile builder's whole furniture stage, so a test or an audit plans exactly what the game plants: the roads about the tile in the builder's order (`roadCells`, `src/simulation/road-cells.ts`), the ground nothing stands on (building hulls, rail corridors, tunnel approaches, Greenway parcels, the ICA's forecourt), the Mall's planned lawns as `reserved`, crowns under decks, the tile's own draws for Boylston Street, then `planStreetSigns` with a pole only where the tile sees no roadway, deck or stall. Decks and footbridges are not in the pavement and keep their ribbons (`raised`); a tile without `streetPavement` keeps the survey build's ribbons. `BuiltTile.posts` lists every tree place, lamp and sign pole of a tile. `street-life.ts` tests its walks against the same ground when the streamer's tiles are at hand (`tiled`): a sidewalk stretch lies 1.1, 1.65 or 2.2 m beyond the kerb (`kerb`: the middle one of the edges `roadwayEdge` measures every 4 m beside the segment), and every 0.75 m point of it, with the two points between it and the one before (`stepClear`: a kerb's corner reaches in between two points), keeps 0.45 m to the roadway and the stalls and clears the posts of every resident tile in reach (`drawnClear`); park paths and the Mall's files are tested the same way, and kerbside cars stand 1.1 m inside the kerb, nose and tail on the pavement, stood once the spawn's own tile is resident (`park`: at once on a desktop, later for a phone that resumes somewhere else, so `parkedCount`, `meterCount` and `parkedColliders` are live). A walk is verified once and kept (`verify`); while a tile it needs is not resident it has no routes and is asked again when the resident tiles have changed (`unseen`, `residents`), and the walkers the spawn's tiles cannot place wait on stretches of their own beyond the city's edge until `refill` calls them, so the pool stays 112. `tests/street-furniture.test.mjs` (synthetic tiles, Newmarket Square, Blue Hill Avenue), `tests/street-furniture.spec.ts` (`__backbay.streetside()` at the spawn and at Newmarket Square) and `npm run audit:furniture` (`scripts/audit-street-furniture.mjs`, in the validation workflow: every tile planned and every walk verified with all 265 tiles resident, each place then held against the polygons read with no index, `drawnGround` in `tests/helpers/street-furniture.mjs`, and every walk against every post through an index of the script's own) cover it; `loadTileHeaders` in `tests/helpers/metro-city.mjs` reads every tile's header without its shells (`parseTileHeader`). Traffic signal masts (`signal-placement.ts`) are still placed by class width at their junctions and are not part of this: 693 of 2,419 stand in drawn pavement.
- **Water-crossing decks are levelled per chain, not per segment.** `build-metro.py` profiles each Boston GIS segment alone: a node with a positive source level, or inside mapped water, sits 6.4 m above the raw DEM there (`deck_profile`). On a bridge over water that lifts the bank nodes 6.4 m above the quay and the water nodes 6.4 m above the water, so the Summer Street and Congress Street bridges over Fort Point Channel humped 4.4 m inside their 10 m junction stubs beside Dorchester Avenue. `scripts/level-water-crossings.py` (library `scripts/water_crossings.py`, in the chain right after the merge) joins elevated pieces through their lifted nodes, and every chain that reaches mapped water with all its lifted land nodes within 60 m of it gets one deck surface: the inverse-distance blend of the chain's own at-grade junction heights along the chain (a bridge between streets of different height slopes across the water instead of climbing inside a stub), where each lower bound raises its nearest junction's effective height until the surface meets it: 0.3 m over the graded terrain under the deck pieces and under each ramp (fading out over the 10 m before the pinned landing), 1.5 m over the water plane, 6.4 m over any road crossing beneath. Ramp pieces keep the ground landing the grader pinned, smoothstep to the deck and are held just over the terrain point by point, since the grader never grades under an elevated piece and that terrain is the collider and drive surface. Chains with a dedicated builder (Harvard, Longfellow, Bowker, Tobin, Chelsea Creek, Leverett, source-connection approaches) and chains reaching inland viaducts (Broadway, Frontage Road, North Washington Street) are recorded in `provenance.waterCrossingDecks.skipped`, never changed. `validate-city.py` fails when a rerun would still change a profile. The GIS also splits a road at its junction node, so a land overpass often starts its 6.4 m climb inside an 8 to 20 m stub; that class is untouched: 47 elevated pieces keep grades above 25% (173 above 8%).
- **Land approaches are repaired after the water crossings.** `scripts/level-land-approaches.py` (library `scripts/land_approaches.py`, right after `level-water-crossings.py`; water-crossing chains, dedicated builders and tunnels are never touched) fixes three things the per-segment lift leaves broken, found at the Route 9 / Jamaicaway interchange. A *seam stub* is a single elevated piece whose lifted node is where a terrain-following road ends and continues its bearing (cosine 0.9) with no road crossing beneath and no terrain road passing through: the level marked a culvert, not a 6.4 m structure, so the node is brought to the ground the continuing street arrives on and the piece re-profiled from its pinned landing, held just over the terrain; a piece then within 0.2 m of the terrain everywhere drops its `elevations`, `bridge` and levels and becomes a surface street (Huntington Avenue's two 15 m stubs at the Brookline line, which climbed 6.2 m to a cliff), otherwise it keeps a level-0/0 deck (Blue Hill Avenue, the Riverway stub). A *sunk approach* is a ramp or deck piece whose straight profile runs more than 5 cm under the DEM embankment between its fixed ends (the Jamaicaway carriageways sat 0.7 m inside their own approach lawn); it is held point by point over the terrain like a water-crossing ramp, then pulled taut (`taut`, the upper concave envelope between the ends) so it does not copy every 3 m step of the DEM. `TOWN_LINKS` restores the last vertex of OSM way 48918271 (the Pond Avenue ramp, clipped at the Boston strip beyond the 10 m snap) and snaps it to the Jamaicaway loop node. `provenance.landApproaches` records the seams, floored pieces and links with their source profiles (`restore_sources` puts the roads back before a rerun redoes the same repairs); `validate-city.py` fails when a rerun would still change a road or when replaying the records from their sources does not reproduce the installed roads.
- **The northern towns (Everett, Medford, Malden, Melrose) were added last, on the committed package.** `scripts/merge-north-extension.py` keeps the baseline package (commit 9392b18, which already held Chelsea) byte for byte and takes only what the four towns add from a fresh `build-metro.py` / `grade-terrain.mjs` run; the terrain lattice grew 1,070 rows north (`fetch-terrain.py --anchor`), new streets get fresh grading with a 30 m / 90 m blend, and every town curb is regenerated from one union so a street crossing a town line is not capped. Each town clips its OSM ways to its own outline, and neighbouring outlines leave slivers and overlaps of a few metres (pieces under 3 m are dropped), so a street crossing a line between two towns stopped short of its continuation: `connect-source-seams.py` first leaves a street that both sources carry with one record (`source_copies` in `source_seams.py`: a surface town road lying within 3 m of surface Boston segments all along its own length and running their way leaves the package, then a Boston segment lying so along a town road, the stub of a town street; nine records, Brookline's six pieces of Saint Mary's Street on both sides of the Turnpike bridge among them, kept with their list positions in `provenance.sourceCopies`, which a rerun puts back first; a copy that a road meets at a vertex the record it copies does not have is held back, and `validate-city.py` fails on one, as it does on any record still lying along the other source's line; the copies of a bridge stay the Turnpike stage's, `bridge_copies`), then carries each such dangling end within 20 m of a shared town edge along its source way (and the ways leaving that way's end node), at most 20 m, to the road it meets (`town_seams` in `source_seams.py`: that road's end, or a vertex inserted for a junction; overlapping pieces of one way meet in the middle; each changed road keeps its original points in `townSeam`, `provenance.townSeams` lists the joins, and this also joined the older Cambridge/Somerville breaks). The same step carries a bridge split at a town line as one deck (`town_bridge_joints`: Boston Avenue over the Mystic River at the Medford/Somerville line had dropped 3.3 m to the river at the joint) and holds a bridge the map edge cuts mid-span level from its landing (`edge_bridge_stubs`: Route 60 into Arlington); both keep their original profile and levels in `townSeam`. Where a town street continues across a town line at another nominal width, `width_tapers` in `street_surfaces.py` adds a smoothstep taper to the curb union so the curbs and the pavement measured between them do not step at the line. MassGIS town outlines also stop at tidal shores, so the clipping dropped river spans: the same script restores them (`restore_clipped_spans`: an uncovered stretch of a source way, at least 30% over water, whose ends meet dangling road ends) as `restored-water-span` decks the water stage then levels, recorded in `provenance.clippedWaterSpans`. Several roads can share one id (a way clipped in two towns, or at both shores of a river), so key per-road state by the road object or its position, never by `id` alone (`water_chains` once gave one bank piece the other's stations). Houses there are generated from the MassGIS assessor parcel under each OpenStreetMap footprint (`scripts/house_shapes.py`: storeys set the eave, the style sets the roof over the footprint's rectilinear parts, a Victorian's corner bay becomes a turret; `houseStyle` metadata), painted by `src/render/house-styles.ts` (mirrored by `house_palette()` in `building_semantics.py` so the far box matches) and detailed by `house-plan.ts` / `house-details.ts` (porches, towers, chimneys, garage doors); `scripts/house_driveways.py` lays a lane beside each house from the parcel, in the frame of the street segment nearest the house (`street_frame`: where the nearest point is a vertex two or three segments share they are exactly as near, 711 of the 36,014 houses with a street in reach, and the one with the lowest centre z, then the lowest centre x, is taken, never the first the STRtree returns: that order shifts with every road added or removed anywhere in the metro, and taking two streets out of Brookline had turned ten houses' frames from Medford to Melrose). `src/simulation/town-centres.ts` names the four town centres: `src/render/town-frontages.ts` paves shopfront forecourts there and `activity.ts` makes them at least mixed. `src/render/melrose-landmarks.ts` hand-models the Melrose YMCA and three park structures in place of their extrusions. `scripts/north_overpasses.py` (`level-north-overpasses.py`, right after the land stage) repairs Sweetser Circle, the Mystic Valley Parkway over Main Street (trenches under the decks) and Florence Street (an embankment, bridge kind `north-overpass-deck`, owned so earlier stages replayed by the validator leave it); the land stage leaves those decks alone. Static Orange Line and Haverhill Line track is a separate optional sidecar, `public/data/rail.json`, written by `scripts/build-rail-tracks.py` (library `rail_tracks.py`, from `osm-metro-railways.json`) on the finished package and drawn by `src/render/rail-tracks.ts`; it records a digest of the streets and grids it was built on (`package_digest`), which `validate-city.py` compares, so rerun it after any road or terrain change. No trains run on it.

The builds are ordered and budgeted from the observer's motion (`src/render/stream-order.ts`, pure and node-tested): the streamer keeps a smoothed ground velocity from the positions it is given (a jump over 80 m or a gap over half a second resets it); the wanted window is the tiles around the observer plus, above 8 m/s on desktop, those around the point `LOOK_AHEAD_S` (8 s) ahead; tiles build in order of their distance from that point (`orderTiles`; a road that reaches the view keeps its owner tile's head start). Several tiles can be under construction: every downloaded wanted tile first runs to `structuresReady` (terrain, deck meshes and colliders, so bridges and viaducts stand about 1.5 km out at helicopter cruise), then tiles are finished one at a time, the one in progress keeping its turn unless another is 250 m more pressing; a build that calls `nextFrame` (waiting for a shader link, or after its upload slice) rests and the next tile takes the remainder of the frame's slice. The slice (`buildSlice`) is the spare frame time (0.5 to 4 ms against a 60 Hz frame), raised with speed to the full 4 ms as the most pressing ready tile comes due (its score from 1,000 m down to 700 m), and to 10 ms as an unbuilt ready tile comes within 400 m. Deck parapets come from `bridgeBarriers()` (`src/simulation/road-surfaces.ts`) for rendering and physics alike; they skip edges whose deck sits within `RAIL_LIP` (0.35 m) of the terrain probed 0.3 and 1.5 m outside the rail, unless that terrain falls more than `SHELF_DROP` (0.75 m) within 4 or 7 m (`deckEdgeGrounded`), a test waived within `MOUTH_REACH` (12 m) of a junction with another street (`junctionMouths`; the same street continuing onto its bridge, as at Alford Street, is none), so a ramp mouth or at-grade approach has no wall across the street junction it lands in while an approach on a graded shelf above an embankment keeps its rail. Traffic follows `roundedPath()` in `src/simulation/traffic.ts`, whose `roadAt[k]` is the road of the segment that starts at rounded point k (the lane departing a junction, not the one arriving), which is what decides an NPC's height when a deck meets a terrain street. Traffic and transit add bodies to this same world; the helicopter (`src/simulation/helicopter.ts`) uses it for clearance queries.
- **Walk mode** (`TravelMode` `'walk'`, key 4) is `src/simulation/walker.ts`: a capsule on a kinematic body moved by Rapier's `KinematicCharacterController` in the driving world, stepped at 60 Hz just before `physics.step()` (the controller reads the collider pose the previous world step wrote). The capsule collider is disabled (`setEnabled(false)`), so no vehicle, wheel ray, camera ray or flight sweep feels it; the controller still sweeps its shape. Three things about this controller in Rapier 0.21 are load-bearing: its skin must stay at 5 cm (`SKIN`; at 2 cm the capsule creeps 15 cm into flat ground within seconds), a grounded walker presses down only 0.3 m/s (a larger downward step stalls autostep at curbs), and its query filter must be `QueryFilterFlags`, never a predicate that calls a collider method (`c.isSensor()` re-enters the borrow the query holds: the move is wrong and `world.free()` later throws). A ray from the body's middle keeps the feet from ending a step below the fixed surface. Movement is relative to `viewYaw` (the camera heading: mouse drag, Q/E and the right stick turn it, strafing swings it), the body's `yaw` turns to the direction of travel; `main.ts` folds the drag `lookOffset` into `viewYaw` each frame. `closestSidewalk()` (R, and landing from the helicopter) is the curb of the nearest surface street plus 1.3 m on the walker's side, the other side or the next street when a building or collider is there. Knock-downs are `src/simulation/knockdown.ts`, shared with the sidewalk walkers in `street-life.ts`: `walker.strike()` tests the walker against `traffic.obstacles()` and `transit.obstacles()` each step, and the walker is passed to both as an external obstacle so they brake for it. The vehicle left behind keeps its brakes on (as in flight); returning to it from more than 12 m away calls `DrivingPhysics.resetNear()`. `src/render/player-model.ts` draws the walker with one instance of `createPedestrianModel(..., {closeUp:true})` (anatomical proportions, a modelled neck; the `run`, `air`, `gaze` and `look` fields of `PedestrianAppearance` pose and dress it) and passes the gait `distance` in walking strides (`strideScale`), so a planted foot does not slide when the pace changes. Touch reuses the flight pad (`.walking` mirrors the `.flying` layout rules in `style.css`).
- **The Commonwealth Avenue Mall** is a hand-set plan, `src/simulation/commonwealth-mall.ts`, drawn by `src/render/commonwealth-mall.ts` from `cityParkDetailSteps`. Boston types its lawns "Malls, Squares & Plazas", which the park renderer and the tire sampler pave: `isCommonwealthMall` makes them lawn in both (`city-parks.ts`, `tire-tracks.ts`). The centre walk is not generated: each block has one Sidewalk Inventory polygon (the 6.2 m walk, the paving round each monument, the island left open there, the cross street sidewalks), so a mapped path on the Mall that the tile's surveyed polygons cover for 80% of its length is not drawn, and any other (the walk west of the Massachusetts Avenue underpass, the Kenmore block) is paved in the sidewalk concrete through a `DrapedSurface` (`ParkOptions.sidewalks`, `paving`). `MALL_BLOCKS` (each lawn's axis, where the walk enters each fenced end and how far the cross street sidewalk overlaps the lawn there) and `MALL_MONUMENTS` (the centroid of each island) are numbers measured on the package; `tests/commonwealth-mall.test.mjs` holds every one to the installed tiles, so run it after a rebuild that touches parks or sidewalks. `planMall(parks)` is pure and the same whichever lawns a tile sees (each block draws its own random sequence before any test on a lawn outline); a tree, bench, fence panel or monument belongs to the tile its position falls in. Fence pickets are one cutout quad a panel (an `alphaMap` mask, `alphaTest` with coverage on desktop, `userData.noAO` since GTAO's normal pass cannot cut it out) between box rails and posts; fence panels and monument plinths are solid boxes handed to `DrivingPhysics.addParapets` through `ParkOptions.onSolids`. Street trees and their grates keep off the planned lawns and the sidewalk before each fence (`mallGroundTest`, the `reserved` ground of `tileFurnitureSteps` in `street-furniture.ts`). Monument geometry (`buildMonument`, `statueFigure`) is DOM-free and node-tested.
- **Sidewalk walkers also walk park paths** (`street-life.ts`, `src/simulation/park-walks.ts`). A walker paces one straight stretch, so each mapped park path gives its straight chords (`straightRuns`: the longest chord every vertex between stays within the lane's tolerance of, 10 m or more; a path of 4.5 m or more in two files), checked like a sidewalk stretch and for water (by source basin: the harbour and rivers are one 8,000-point outline), cut into the same 22 to 44 m pieces, one walker each. A metro lists no paths of its own: they come from the resident tiles (`StreetLifeOptions.tiles`, the streamer), verified the first time a neighborhood asks and kept by path id. A park stretch is named for the street nearest it (the same-street bonus then fills the walks beside the street being driven) and scores `PARK_DRAW` metres nearer than a sidewalk; the pool and the local targets are unchanged. The Mall's planned blocks are walked in two files from `mallWalkLanes()` (on the surveyed walk, short of the fences and of each monument's paving) instead of from their mapped paths, and `sidewalkClear` keeps the avenue's sidewalk stretches off its lawn. With the streamer's tiles at hand every stretch, sidewalk or path, is tested against the roadway, stalls and posts those tiles draw rather than against the streets' ribbons, and waits for the tiles it needs (see the entry on what stands beside a street).
- **Frame cost conventions.** The scene's world matrices are refreshed once per frame: `scene.matrixWorldAutoUpdate` is false and the tick calls `scene.updateMatrixWorld()` after the last transform change and before the frame's first render (the reflection probe, GTAO's normal pass and the view would each walk the scene otherwise), so anything that renders the scene outside the tick (`drawResident`) or moves an object after that call (the probe in `updateReflections`) must update it itself; a finished tile's subtree is frozen (`freezeTransforms` in `static-batches.ts`, desktop and phone). On desktop `staticDetailBatchSteps` writes each static part into its `BatchedMesh` already placed, so every part shares the identity matrix, and `cullStaticBatch` replaces three's per-pass `onBeforeRender` (matrix read-back, depth sort and draw-to-part texture upload for every part, for the view, the shadow map and the GTAO normals) with six plane tests against bounds taken once, none while the camera sees the whole batch; it writes three's private `_multiDrawStarts`/`_multiDrawCounts`/`_multiDrawCount` (three is pinned at 0.186.1; if those change shape the batch keeps three's own culling), and `tests/static-batches.test.mjs` checks it draws exactly the parts three's cull would. `graphics.ts` sorts opaque draws so each program variant of a material (batched, instanced, plain) runs together (variant first under GTAO's override material), and takes GTAO's hidden points and lines from the same scan as the `noAO` exclusions (both refresh when `scene.userData.version` changes) instead of two scene walks a frame. `DrivingPhysics.step` calls `world.physicsPipeline.step` directly: `world.step()` also maps handles a step created or removed (soft bodies only) with two wasm calls per collider. Sidewalk walkers are partitioned each frame (`flush(shown)` in `pedestrian-model.ts`): those within `WALKER_REACH` (10 m, their shadow's reach) of the main view's frustum come first in every instanced part, the view and its shadow map draw that count (`mainCamera`), any other camera (a reflection capture) draws everyone, and a phone does not pose the rest (`poseHidden`). The Green Line's rail, bed, wire and poles are built per 320 m cell as the observer comes within the 1.4 km they are drawn at and dropped 400 m beyond (`transit-tracks.ts`). Tunnel light and marking cells wholly beyond the fog's far depth are skipped while the observer is above ground (they stand below every horizon, so what shows instead is fog-coloured too). New geometry reaches the GPU a slice a frame on desktop (`src/render/paced-upload.ts`): `gl.bufferData` is wrapped so that, during one stand-in draw of a new mesh into a one-pixel target, an array over 128 KB only reserves its storage (three then holds the buffer and vertex array state as usual) and its contents follow through `gl.bufferSubData` on the `COPY_WRITE_BUFFER` binding, 512 KB a frame while the build is paced (more fills the browser's transfer buffer and the call waits for the GPU process); the mesh stays hidden until complete. Static batches go through it once their programs are ready, a tile's remaining meshes (shells, a lone surface) before the tile shows, and `graphics.prepare(scene)` sends every texture and large array of the scene while the game loads, so a landmark does not upload in the frame that first sees it. Phones keep first-draw uploads: their arrays are freed on upload and their buffer budget counts what was drawn. Shader programs: `warm` is memoized per material and variant and its readiness check performs the program's first use (`getUniforms`) as soon as it has linked; `warmPasses(scene)` links the shadow and normal pass variants of every mesh at startup and `settlePrograms()` waits for them. three's first-use queries wait for the GPU process to drain its queue, 30 to 40 ms in the middle of a pass, however long ago the link finished. The depth stand-in must mirror `WebGLShadowMap.getDepthMaterial`, which passes `map`, `alphaMap` and `alphaTest` on from every caster, cutout or not. The flight shadow map spreads 4,096 texels over 2.2 km (0.54 m each), so `fineCasters` in `world.ts` switches `castShadow` off for the facade depth, storefront, signal and lamp pole meshes of loaded tiles while flight shadows are on (they leave no mark in it and were half the pass's triangles) and back on for the ground views. Shore bank and rock colliders are added in runs of 8,192 triangles between frames (`src/simulation/mesh-chunks.ts`): a harbour tile's bank is 190,000 triangles, 40 to 58 ms for Rapier in one call, under 3 ms a run. Runs meet at seams the engine's internal-edge fix does not see across; measured on a bank of that size, 240 random twelve-second walks and runs never stall and differ from the whole mesh by at most a one-frame blip of a few millimetres at a seam (`tests/collider-runs.test.mjs` holds a small version), and sliding car bodies travel the same distance. The terrain tile's own trimesh (about 20 ms, once a tile) is still built whole; bounds of generated parts come from `computeBounds` (`src/render/fast-bounds.ts`, bit-identical to three's `computeBoundingBox`/`computeBoundingSphere`); `tunnelPortalBoundsIntersect` looks only in the portal cells a query touches; the TD Garden's finishes and the northern towns' house materials are painted while a desktop loads (40 ms of canvas work each; a phone paints them with the first tile that needs them). Traffic's `respawnAway` takes its candidates from `spawnByComponent` (built once) and a car that finds no place asks again a second later: twelve fresh routes a frame per stranded car, each after a pass over every edge of the metro, held the frame at 30 ms for seconds of a full-speed flight over the northern towns. The minimap's map (`drawMap` with `pad`) is drawn every 90 ms into a layer 16 px larger than the minimap on every side and copied onto it every frame, shifted in whole device pixels by what the player has travelled since, with the player's arrow and the destination marker drawn over it (`composeMiniMap`); its width comes from a `ResizeObserver`, since reading `clientWidth` in the frame loop forced a layout every frame. Trees (`src/render/foliage.ts`) are instanced in three pools per species by distance from the observer (`LOD_DISTANCE`: 100 and 320 m, 60 and 210 m on Balanced), sorted four times a second or every 25 m. Each level has its own arrangement of leaf cards (48, 24, 12), so a whole-tree swap showed, most of all from the helicopter (at 160 m up the second boundary is a ring 277 m out, in the middle of the view). A level's leaf geometry therefore also holds the next level's cards: the vertex shader injected by `wind` (view and shadow materials alike) scales each card about `cardCentre` by its `cardFade` tag and the blend over `treeLodBands`, which ends `LOD_LAG` (15 m, more than the observer travels between two sortings) short of the pool boundary, so a pool swap changes nothing on screen. The blend takes the distance from the `treeObserver` uniform, not `cameraPosition`, which in the shadow pass is the sun's camera.
- `src/render/window-interiors.ts` injects the parallax window-interior shader into the façade materials through `onBeforeCompile`; its `windowGrid()` also drives the canvas painter in `materials.ts`, so the two stay aligned by construction. Near windows show rooms, far windows fall back to the painted texture and emissive map, and the wall below tile row zero (a neighborhood profile's raised ground floor) is drawn as foundation with basement lights rather than the texture's wrapped window row.
- `src/render/world.ts` builds the static world (terrain, roads, parks, water, far city) and, for a metro package, starts the tile streamer; `src/render/tile-geometry.ts` turns a tile's quantized shell into the same non-indexed, UV-stabilized geometry the old GLB path produced. Landmark-specific modules (`prudential.ts`, `state-house.ts`, `fenway-park.ts`, `metro-landmarks.ts`, etc.) select a building by its source ID or `landmark` tag, split its shell for custom materials, and may add extra colliders. Fenway, the Prudential complex, 145 Dartmouth, the BUMC ambulatory care center, NEXUS in Allston, the Logan terminals and the Zakim Bridge use exact mesh collision (`src/simulation/building-collisions.ts`). Buildings whose convex hull crosses a ground-level road also carry generated `collision: "mesh"` metadata. BUMC has a verified passage correction in `scripts/building_passages.py`; exact collision alone did not remove its source walls. Other buildings use convex footprints. A tile building flagged `structure` (the Zakim) gets no foundation skirt and carries a token footprint. The tile builder dresses the Zakim's mesh at runtime from one trace of its carriageways (`surveyDeckCarriageways` in `src/simulation/survey-deck-lanes.ts`, which leaves out strips mostly under another deck, the tower struts): generated piers (`viaducts.ts`), asphalt over every deck face a traced carriageway crosses (minus faces a road deck paves) plus lane paint (`survey-deck-surface.ts`), and concrete parapets where the survey leaves an edge open over a drop (`src/simulation/survey-deck-parapets.ts`, drawn by `addSurveyDeckParapets` and collided by `DrivingPhysics.addParapets`; a road deck reaching the edge keeps its own rail). Each step, and the pier planning (`surveyViaductSupportSteps`), takes about 0.1 s, so each runs as a generator that pauses between small units of work (a pier section, a station, a batch of grid entries; the builder then draws the parapet boxes 32 at a time and adds their colliders 64 at a time) and the builder passes a pause on only once the frame's deadline has passed (`paced` in `tile-builder.ts`).
- `src/simulation/` is non-visual logic (roads, signals, traffic, transit, activity density, audio); `src/render/` builds meshes; `src/ui/` is DOM interface plus Canvas minimap/atlas.
- World coordinates are meters: X increases east, Z increases south, Y is height above a local datum (not sea level). Conversion from State Plane feet is documented in DATA_SOURCES.md.

### Node-test constraint on `src/`

`tests/*.test.mjs` import `src/**/*.ts` directly under plain Node (no bundler). Any module reachable from those tests must:
- use explicit `.ts` extensions on relative runtime imports (extensionless `import type` is fine since it is erased),
- use only erasable TypeScript syntax (no enums, namespaces, or constructor parameter properties),
- avoid Vite-only features such as `import.meta.env` at module load.

`main.ts` and pure render modules use extensionless imports because only Vite loads them.

The baseline is the committed package before the northern towns (commit 9392b180fc913e7428df7170a9eb6bc1b984ad75; the merge records the commit string it is given, so keep `9392b18` to reproduce the shipped provenance). The strict road audit currently fails on the 18 remaining approach profiles in `reports/road-generation.json`; treat that as an explicit review gate for extensions. Ground-road strips are globally unioned and tile-clipped by `street_meshes.py`, not independently capped by the renderer. The connected-profile stage preserves fixed ground landings and dedicated joins, while reporting impossible terrain/grade/clearance constraints. Sullivan's reviewed straight bridge, Maffa corridor and paved-area inputs live in `public/data/sullivan-square-source.json`; `reviewed_road_inputs.py` applies them during land/surface generation, and both provenance hashes must match. ## Deployment

Hosted on GitHub Pages at https://markleary.github.io/drive-boston/, published by `.github/workflows/deploy.yml`: every push to `main` first calls `.github/workflows/validate.yml` (physics, Python generator tests, data validation and road-audit regression gate), then runs `npm ci` and `npm run build` on Node 24 and deploys `dist/` with `actions/deploy-pages` (the Pages source is GitHub Actions, not a branch; the old `gh-pages` branch is unused). Validation also runs on pull requests; browser visual QA remains a local pre-merge check. `vite.config.ts` uses `base: './'` so the build works under a repository subpath.
